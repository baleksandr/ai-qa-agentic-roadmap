# Concept 08 — A2A

> **migrationStatus:** `partial` — Study Mode: 8 розділів (PART II пакет 4).

## Review Mode

**Проблема:** агенти на різних сервісах мають обмінюватися задачами без спільного monolith harness.

**Ідея A2A (agent-to-agent):** **протокол повідомлень** між агентами (delegate task, status, result) — код транспорту + контракт, не LLM «телепатія».

**Для QA:** security меж агентів, correlation id через chain.

## Study Mode

### Навіщо A2A?

Investigation agent на сервісі QA делегує coding agent на сервісі dev: `TaskSpec` + evidence bundle. Відповідь — `PatchProposal`, не вільний чат.

### login_spec ланцюг

Investigation → A2A delegate → Coding accepts → works → A2A result → orchestrator closes workflow.

### Код vs LLM

LLM всередині кожного агента; A2A messages — structured API між сервісами.

### Збої

Spoofed agent, replay attack. **QA:** mTLS, signed tasks, tenant scope.

### Запам’ятати та співбесіда

A2A — **міжсервісний контракт** агентів.
