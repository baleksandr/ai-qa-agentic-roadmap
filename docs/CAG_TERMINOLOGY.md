# CAG: два значення одного акроніма (не змішувати)

Публічний сайт і атлас **не використовують ярлик «CAG» без уточнення**. Нижче — офіційні назви, визначення та джерела для обох варіантів.

## 2. Cache-Augmented Generation (книга AI Engineering 2025)

| Поле | Зміст |
|------|--------|
| **Назва в UI** | **Cache-Augmented Generation (книга)** — окремо від V10 |
| **Джерело** | *AI Engineering*, 2025 Edition — розділ **«RAG vs CAG»**, друк. **с. 141–143** |
| **Суть (своїми словами)** | Стабільну частину знань **повторно використовують через кеш** (у книзі — шар KV memory / не re-fetch з vector DB щоразу). Динамічне лишається на retrieval. |
| **Потік (книга)** | Static layer → cache у моделі; dynamic layer → vector retrieval → доповнення до prompt |
| **Варіант на атласі** | Опційний перемикач **«Prefix cache (книга: Cache-Augmented)»** на схемі V10 — показує **додатковий** механізм провайдера, не замінює підготовку context |

## 3. KV caching / prompt caching — не «третя лінія», а механізм

| Рівень | Що це |
|--------|--------|
| **Архітектурний підхід (книга)** | **Cache-Augmented Generation** — *що* кешуємо (стабільний шар знань) і *навіщо* (швидше/дешевше inference разом із RAG) |
| **Механізм inference (книга)** | **KV Caching in LLMs**, друк. **с. 326** — *як* провайдер/runtime зберігає обчислений prefix (ключі/значення attention) між запитами |
| **Prompt caching (практика API)** | Політика провайдера щодо повторного використання **однакового prefix** у billing/latency |

**Різниця:** Cache-Augmented Generation описує **розподіл static vs dynamic knowledge** у RAG-системі. KV / prompt caching описує **технічне повторне використання** вже обробленого prefix — це інструмент, яким Cache-Augmented може користуватися, а не окремий «третій CAG».

V10 §3.6 (prompt caching) узгоджується з **механізмом**, не з назвою Context-Augmented курсу.
